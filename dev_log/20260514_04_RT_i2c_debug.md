## 二、uart.v 复位极性 Bug（上板前发现）

### 问题

sID 上板验证时，UART 接收到的第一个字节为 `0x00`，随后才是 `2025210860`。

### 根本原因

`uart.v` TX 状态机复位时 `tx_reg <= 1'b0`（TX 引脚低电平），而 UART 空闲状态应为高电平（MARK = 1）。FPGA 复位期间 TX 持续低电平，PC 端 UART 将其解码为一个 START + 全零字节 = `0x00`，复位释放后 TX 恢复高电平构成 STOP 条件。

### 修复

```verilog
// rtl/perips/uart.v
// 修复前
tx_reg <= 1'b0;
// 修复后
tx_reg <= 1'b1;   // TX 空闲为高电平（MARK），避免复位期间产生虚假 START 位
```

- UART 发送温度字节：正确 ✓

问题锁定在 **I2C 通信本身**。

## 四、i2c.v 历次修复

### 4.1 复位极性错误（根本 Bug）

**问题：** 原始 i2c.v 使用 `if (rst)` 判断复位，项目约定 `RstEnable = 1'b0`（低有效），导致正常运行期间（rst=1）每个时钟沿都把 `ctrl_busy` 强制清零，I2C 事务永远无法启动。

**修复：**

```verilog
// 修复前
if (rst) begin
    ctrl_busy <= 1'b0;
    ...
// 修复后
if (rst == `RstEnable) begin
    ctrl_busy <= 1'b0;
    ...
```

同理修复 half_cnt 计数器：

```verilog
if (rst == `RstEnable || state == ST_IDLE)
    half_cnt <= 9'd0;
```

### 4.2 CTRL 寄存器读回 bit 位置错误

**问题：** 添加 `ctrl_two_byte` 后，读回寄存器中 `ctrl_busy` 移到了 bit[11]，而 RT 状态机轮询的是 bit[9]，导致 POLL 状态立即退出（读到 ctrl_two_byte=0 误判为 BUSY=0）。

**修复：** 调整字段顺序，确保 `ctrl_busy` 在 bit[9]：

```verilog
// 修复后
2'b01: data_o = {21'h0, ctrl_two_byte, ctrl_busy, 1'b0, ctrl_rw, ctrl_addr};
//                               ↑bit10      ↑bit9
```

### 4.3 RDATA 寄存器地址简化

原设计为 2 字节读新增了 `RDATA_B1`（地址 `0x7004_0000`），reg_sel 扩展为 3-bit，RT 状态机需要两次总线读（RT_RD_B1 + RT_RD_B2）。

**简化：** 删除 `0x7004_0000`，将 MSB 和 LSB 打包进原 `0x7003_0000` 返回：

```verilog
2'b11: data_o = {16'h0, rdata_b1, rdata_r};
//                      [15:8]    [7:0]
```

RT 状态机读一次 RDATA，直接取 `mem_rdata_i[14:7]` 得温度（0.5°C/bit）：

```verilog
RT_RD: begin
    rt_temp <= mem_rdata_i[14:7];
    ...
end
```

### 4.4 去除写 Pointer 阶段

原 RT 状态机先做一次 I2C 写事务（写 Pointer=0x00），再做读事务。LM75 上电默认 pointer=0x00（温度寄存器），与参考设计（i2c_read_lm75.v）对齐，直接去除 WRITE 阶段。

**简化后状态机（仅 3 状态）：**

```
RT_WR_CTRL_R → RT_POLL_R → RT_RD
```

CTRL 写入值：`0x0000_05C8`（TWO_BYTE=1, START=1, RW=1, ADDR=0x48）

### 4.5 ACK 检测改为无条件继续

原设计在 `ST_ADDR_ACK` 阶段检查 ACK：NACK 时直接 STOP，导致 LM75 ACK 因采样时序偏差被误判为 NACK，事务中止，RDATA = 0x00。

**修复：** 与参考设计一致，不检查 ACK 结果，无条件进入数据接收阶段。

```verilog
// ST_ADDR_ACK half=1：无条件继续
if (!ctrl_rw) begin
    state <= ST_WDATA;
end else begin
    sda_out_r <= 1'b1;
    bit_cnt   <= 3'd7;
    state     <= ST_RDATA;
end
```

### 4.6 SDA 采样时机改为 SCL 上升沿

**问题：** 原设计在 `half=1`（SCL 下降沿）采样 `sda_in`。LM75 在检测到 SCL 下降后会立即开始切换 SDA 准备下一 bit，可能导致采样到切换瞬间的不稳定值。

**修复：** 改为在 `half=0`（SCL 上升沿）采样，与参考设计 `if(SCL_HIG): read_data[15] <= sda` 一致：

```verilog
if (!half) begin
    scl_r   <= 1'b1;   // SCL 上升
    half    <= 1'b1;
    // SCL 上升后立即采样（SDA 最稳定）
    shift_r <= {shift_r[6:0], sda_in};
    if (bit_cnt != 3'd0) bit_cnt <= bit_cnt - 3'd1;
end else begin
    scl_r <= 1'b0;   // SCL 下降，推进状态
    ...
end
```

## 五、RT 状态机 rt_done 重触发 Bug

**问题：** 使用 Hold_Freeze（EX stall 改用后）时，id_ex 被冻结保留 RT 指令。RT 完成后 `rt_done` 在次拍清零，但 opcode 仍是 INST_SID，触发条件重新成立，死循环。

**修复：** `rt_done` 不无条件清零，等到 opcode 不再是 RT 指令后才清：

```verilog
end else begin
    if (!(opcode == `INST_SID && funct3 == `FUNCT3_RT))
        rt_done <= 1'b0;
end
```

同理对 `sid_done` 做相同处理，并在 `if(sid_done)` 块中主动释放 hold：

```verilog
if (sid_done) begin
    hold_flag = `HoldDisable;
end
```

## 六、uart_recv.py 重写

将原来固定读 10 字节的脚本改为"等首字节，静默超时自动结束"：

```python
# 等待首字节（最长 wait_sec 秒）
first = ser.read(1)
# 切换为短超时接收后续字节
ser.timeout = idle_sec
while True:
    chunk = ser.read(64)
    if not chunk: break
    buf.extend(chunk)
```

1 字节时自动解读为温度（× 0.5°C）。
