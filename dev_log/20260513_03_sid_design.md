# Send ID（sID）扩展指令设计规划

**日期：** 2026-05-13  
**项目：** Tiny-Risc-V-for-class（RV32IM 三级流水线处理器核）

---

## 一、功能描述

新增一条自定义 RISC-V 指令 **sID**（Send ID）。CPU 译码到该指令时，通过 UART 依次发送学号 `1234567890` 各数字的 ASCII 码值（共 10 字节），发送完毕后流水线继续推进。

| 学号字符 | ASCII（十进制） | ASCII（十六进制）|
|---------|--------------|----------------|
| '1' | 49 | 0x31 |
| '2' | 50 | 0x32 |
| '3' | 51 | 0x33 |
| '4' | 52 | 0x34 |
| '5' | 53 | 0x35 |
| '6' | 54 | 0x36 |
| '7' | 55 | 0x37 |
| '8' | 56 | 0x38 |
| '9' | 57 | 0x39 |
| '0' | 48 | 0x30 |

---

## 二、指令编码

### 2.1 格式

指令采用 I-type 格式（Imm、rs1、rd 字段均不使用，填 0）：

```
 31      20 19  15 14  12 11   7 6      0
┌──────────┬──────┬──────┬──────┬────────┐
│ Imm[11:0]│  rs1 │funct3│  rd  │ opcode │
│ 000…000  │ 00000│ 000  │ 00000│0101111 │
└──────────┴──────┴──────┴──────┴────────┘
```

| 字段 | 值 | 说明 |
|------|-----|------|
| opcode[6:0] | `0101111` | 自定义（RV32A AMO 域，本项目未实现 A 扩展，安全复用）|
| funct3[2:0] | `000` | sID 标识 |
| rd、rs1、Imm | 全 0 | 不使用 |

**指令机器码：** `0x0000_002F`

### 2.2 冲突检查

本项目 ISA 为 RV32IM，未实现 A（Atomic）扩展。opcode=0101111, funct3=000 在现有实现中无任何指令映射，可安全使用。

---

## 三、执行语义

```
sID 执行流程：
  for i = 0 to 9:
      等待 UART TX 空闲
      写 UART TX 寄存器 ← ASCII[i]（学号第 i 位）
  流水线继续推进（rd 不写回）
```

该指令为**多周期指令**，在 EX 阶段持续拉高 `ex_hold_flag_o`，通过 ctrl 产生 Hold_Id 暂停流水线，直至 10 字节全部发送完毕。

---

## 四、实现方案

### 4.1 UART TX 写地址

UART 外设地址：`0x3000_0000`。查 `rtl/perips/uart.v` 确认 TX 数据寄存器的偏移地址（通常为 `0x3000_0000` 或 `0x3000_0004`），以实际代码为准。

### 4.2 字节发送时序

UART 115200 baud 在 50MHz 时钟下：每 bit 约 434 个系统时钟，每字节（10 bit：start+8+stop）约 **4,340 个时钟**。

EX 状态机设计：
- **写阶段（1 拍）**：assert `ex_mem_req_o=1`, `ex_mem_we_o=1`, `ex_mem_waddr_o=UART_ADDR`, `ex_mem_wdata_o=当前ASCII字节`
- **等待阶段（N 拍）**：等待 UART 发送完成（N ≥ 4,500，留余量）
- **共 10 次**，总耗时约 45,000 拍 ≈ 0.9ms

### 4.3 EX 内部状态机

```
新增寄存器：
  reg [3:0]  sid_byte_cnt;   // 字节计数器（0~9）
  reg [15:0] sid_wait_cnt;   // 等待计数器（0~N_WAIT）
  reg        sid_active;     // sID 执行中标志

状态转移：
  IDLE（sid_active=0）:
      检测到 sID 指令 → sid_active=1, sid_byte_cnt=0, sid_wait_cnt=0

  WRITE（sid_active=1, sid_wait_cnt==0）:
      assert UART write with ASCII[sid_byte_cnt]
      sid_wait_cnt ← 1

  WAIT（sid_active=1, 0 < sid_wait_cnt < N_WAIT）:
      sid_wait_cnt++
      ex_hold_flag_o = 1

  NEXT（sid_active=1, sid_wait_cnt == N_WAIT）:
      sid_wait_cnt ← 0
      if sid_byte_cnt == 9: sid_active ← 0  // 发完
      else: sid_byte_cnt++

在 sid_active=1 期间，ex_hold_flag_o 持续为 1 → ctrl 产生 Hold_Id → 流水线暂停
```

## 五、需要修改的文件

| 文件 | 改动内容 |
|------|---------|
| `rtl/core/defines.v` | 新增 `` `INST_SID_OP ``（opcode 常量）和 `` `INST_SID_FUNCT3 ``（funct3 常量）|
| `rtl/core/id.v` | 新增 sID 指令识别分支（opcode+funct3 匹配），向 id_ex 传递 `inst_sid` 标志 |
| `rtl/core/id_ex.v` | 新增 `inst_sid_o` 流水线寄存器，随其余信号一起传递和冻结 |
| `rtl/core/ex.v` | 新增 sID 执行逻辑：状态机、字节计数器、等待计数器；修改 `ex_hold_flag_o`、`ex_mem_req_o`、`ex_mem_we_o`、`ex_mem_waddr_o`、`ex_mem_wdata_o` |

**不需要修改** RIB、UART 外设、SoC 顶层（UART 已挂载在 Slave 3，EX 通过 m0 正常访问）。

## 六、验证计划

### 6.1 仿真验证

编写测试程序：

```asm
# 将 sID 指令的机器码直接放入 ROM
# 0x0000002F = sID
.word 0x0000002F   # sID 指令

# 之后设置 x26=1 表示完成
li s10, 1
loop: j loop
```

仿真中监控 UART TX 数据线，确认：
1. 依次出现 10 个字节：`0x31 0x32 0x33 0x34 0x35 0x36 0x37 0x38 0x39 0x30`
2. 相邻字节间隔 ≥ 4,340 个时钟

需将仿真超时从 500,000ns 扩展至 **2,000,000ns** 以容纳 10 字节发送时间。

### 6.2 回归验证

执行 Basic_Inst_Example 24/24，确认新增逻辑不破坏现有指令。

### 6.3 上板验证

将包含 sID 指令的程序烧入，通过串口终端（115200 baud）接收数据，确认输出字符串 `1234567890`。

## 七、关键设计决策

| 问题 | 决策 |
|------|------|
| 等待 UART 方式 | 固定等待 N_WAIT ≥ 4,500 拍，不读状态寄存器（简化，但占用约 0.9ms）|
| UART TX 地址 | 使用 Slave 3 MMIO 地址（待查 uart.v 确认偏移）|
| rd 写回 | 不写回（rd=x0，遵循"无副作用"惯例）|
| rs1/Imm 字段 | 全忽略，保留给将来扩展 |
| 学号硬编码位置 | 在 `ex.v` 内以 localParam 形式定义，方便修改 |
