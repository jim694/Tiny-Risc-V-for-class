# FPGA 上板验证流程

**日期：** 2026-05-13  
**项目：** Tiny-Risc-V-for-class（RV32IM 三级流水线处理器核）

---

## 一、总体流程概述

```
编写程序（C / 汇编）
    ↓
编译生成 .data 文件
    ↓
Vivado 仿真验证（tb）
    ↓
Vivado 综合 + 实现 → 生成 Bitstream → 下载到 FPGA
    ↓
UART 下载程序到 FPGA ROM
    ↓
按键触发复位 → 处理器开始执行
```

---

## 二、步骤详解

### 2.1 仿真验证

使用 Vivado 自带仿真器对程序进行功能验证。

**testbench 配置**

测试程序路径在 `tb/tinyriscv_soc_tb.v` 中通过 `$readmemh` 指定：

```verilog
$readmemh("../tests/Other_Example/PWM/PWM_inst.data",
          tinyriscv_soc_top_0.u_fpga_mem_bridge._rom);
```

修改路径即可切换被测程序。

**仿真超时**

默认超时 500,000 ns（约 25,000 个时钟周期），适用于普通指令测试。  
PWM 等需要长时间观察的程序，取消注释延长超时：

```verilog
# 500000000 // for pwm
```

**运行方式**

Vivado → Simulation → Run Simulation → Run Behavioral Simulation

---

### 2.2 综合与实现

程序功能验证通过后，在 Vivado 中生成 Bitstream 并下载到 FPGA：

```
Flow Navigator → Generate Bitstream
完成后：Program and Debug → Program Device
```

Bitstream 仅包含处理器核、外设、总线等硬件逻辑，**不包含用户程序**。  
ROM 上电后为空（全零 = NOP），程序通过 UART 单独下载。

---

### 2.3 UART 程序下载

#### 硬件连接

```
PC ──USB转串口适配器──┬── FPGA uart_rx_pin（G15）
                      └── FPGA uart_tx_pin（G16）
```

FPGA 内置 `uart_debug` 模块，当 `uart_debug_pin`（M13，对应板上 Key1）被按下时，
该模块以最高总线优先级接管 RIB 总线，通过 UART 接收数据并写入 ROM（起始地址 `0x00000000`）。

#### 下载工具

使用 `tests/tinyriscv_fw_downloader.py`，该脚本会自动完成：

1. 将 `.data`（十六进制文本）转换为 `.bin`（小端序二进制）
2. 按 35 字节/包协议（1字节包号 + 32字节数据 + 2字节 CRC16-Modbus）发送
3. 等待 FPGA 每包回复 ACK（0x06）

**运行命令（在 ai_dev_2026 Conda 环境中）：**

```bash
D:\coding\Anaconda\envs\ai_dev_2026\python.exe tests\tinyriscv_fw_downloader.py COM口 tests\Other_Example\PWM\PWM_inst.data
```

`COM口` 替换为实际串口号（设备管理器中查看）。

#### 协议说明

| 字段 | 大小 | 说明 |
|------|------|------|
| 包号 | 1 字节 | 包0为头包，包1～n为数据包 |
| 数据 | 32 字节 | 包0中含文件名（byte 1-24）和文件大小（byte 25-28）|
| CRC | 2 字节 | CRC16-Modbus，低字节在前 |

---

### 2.4 触发执行

下载完成后按以下顺序操作：

```
1. 保持 uart_debug_pin（Key1）按下状态
2. 按下 Reset（rst，F20）→ 松开
3. 松开 uart_debug_pin（Key1）
```

> **注意顺序**：必须先按 Key1，再按复位。若复位时 Key1 已松开，uart_debug 不再占用总线，CPU 从 ROM[0] 正常取指执行。

复位释放后，处理器立即从地址 `0x00000000` 开始取指，程序运行。

#### 更换程序无需断电

`_rom` 不在复位逻辑中，**按 Reset 不会清零 ROM**，ROM 内容由触发器保持，断电才会丢失。

更换程序只需重新下载，直接覆盖写入即可：

```
1. 按住 Key1
2. 运行 tinyriscv_fw_downloader.py 发送新程序（从 0x00000000 覆盖写）
3. 松开 Key1，按 Reset → 执行新程序
```

## 三、引脚分配（当前版本）

| 信号 | 引脚 | 说明 |
|------|------|------|
| `clk` | Y18 | 50 MHz 系统时钟 |
| `rst` | F20 | 复位（低有效） |
| `succ` | F19 | LED1：x27=1 时亮（测试成功） |
| `over` | C20 | LED4：x26=1 时亮（测试完成） |
| `uart_tx_pin` | G16 | UART 发送 |
| `uart_rx_pin` | G15 | UART 接收 |
| `uart_debug_pin` | M13 | Key1：按下进入 UART 下载模式 |
| `pwm_o[0]` | E21 | LED2 |
| `pwm_o[1]` | D20 | LED3 |
| `pwm_o[2]` | F14 | 空端口（预留） |
| `io_scl` | M22 | I2C 时钟 |
| `io_sda` | N22 | I2C 数据 |

## 五、辅助工具

### scripts/load_program.py（开发辅助）

用于将 `.data` 文件写入 `fpga_mem_bridge.v` 的 `initial` 块，供**仿真快速切换程序**使用，不用于上板：

```bash
python scripts/load_program.py tests/Other_Example/PWM/PWM_inst.data
```

上板程序通过 UART 下载，不依赖此脚本。
