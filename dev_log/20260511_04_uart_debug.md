# uart_debug 模块学习与包大小修改

**日期：** 2026-05-11
**项目：** Tiny-Risc-V-for-class（RV32IM 三级流水线处理器核）
**涉及文件：** `rtl/debug/uart_debug.v`

---

## 1. 模块定位

`uart_debug` 是**串口固件烧写模块**，允许上位机通过 UART 将新的固件程序写入 ROM，无需 JTAG。

在 SoC 中，该模块作为 **RIB Master 3**（最高优先级主设备）挂接在总线上。当顶层引脚 `uart_debug_pin` 拉高时，`req_o` 置 1，模块占据总线并代替 CPU 直接操作 UART 外设寄存器与 ROM。

```
上位机串口工具
    │  UART 物理线
    ▼
UART 外设（0x3000_0000）
    │  RIB 总线（Master 3，最高优先级）
    ▼
uart_debug 模块
    │  RIB 总线写操作
    ▼
ROM（0x0000_0000 起）
```

模块端口：

| 端口 | 方向 | 说明 |
|------|------|------|
| `clk` | input | 系统时钟 |
| `rst` | input | 复位 |
| `debug_en_i` | input | 模块使能（拉高才工作） |
| `req_o` | output | 总线访问请求（wire，组合逻辑） |
| `mem_we_o` | output | 总线写使能 |
| `mem_addr_o` | output[31:0] | 总线访问地址 |
| `mem_wdata_o` | output[31:0] | 总线写数据 |
| `mem_rdata_i` | input[31:0] | 总线读数据 |

## 2. Packet 结构（修改后）

每个 packet 固定 **35 字节**（first 包与 remain 包格式相同）：

```
索引:    [0]          [1 .. 28]       [29 .. 32]      [33]     [34]
        ┌──────┬────────────────┬────────────────┬──────┬──────┐
        │ 头字 │  固件数据 28B  │  固件大小 4B   │CRC低 │CRC高 │
        └──────┴────────────────┴────────────────┴──────┴──────┘
         ↑                    ← CRC 覆盖范围 rx_data[1..32] →
         不计入CRC
```

| 字段 | 索引 | 字节数 | 说明 |
|------|------|--------|------|
| 头字节 | `rx_data[0]` | 1 | 不参与 CRC 校验 |
| 固件数据 | `rx_data[1..28]` | 28 | 实际写入 ROM 的程序字节（第一包前 28B）|
| 固件大小 | `rx_data[29..32]` | 4 | 仅第一包有效，大端序存储 |
| CRC 校验 | `rx_data[33..34]` | 2 | CRC16-Modbus，大端序：`{rx_data[34], rx_data[33]}` |

**每包写入 ROM 的字节数：** 32 字节（`rx_data[1..32]`，含固件大小字段一并写入 ROM）

> **注：** 修改前 packet 为 131 字节（128字节有效载荷 + 1字节头 + 2字节CRC），固件大小位于 `rx_data[61..64]`。

## 3. 内部寄存器组（修改后）

| 寄存器 | 类型 | 位宽 | 说明 |
|--------|------|------|------|
| `state` | reg | 14-bit one-hot | FSM 状态 |
| `rx_data[0:34]` | reg 数组 | 35 × 8-bit | 接收缓冲区（原为 `[0:131]`，改为 `[0:34]`）|
| `rec_bytes_index` | reg | 8-bit | 当前已接收字节数 |
| `need_to_rec_bytes` | reg | 8-bit | 本包目标字节数（固定为 35）|
| `remain_packet_count` | reg | 16-bit | 剩余待接收的 remain 包数 |
| `fw_file_size` | reg | 32-bit | 固件总字节数（从第一包 rx_data[29..32] 提取）|
| `write_mem_addr` | reg | 32-bit | 当前 ROM 写地址（跨包连续累积）|
| `write_mem_data` | reg | 32-bit | 待写入的 32-bit 字 |
| `write_mem_byte_index0~3` | reg × 4 | 8-bit each | rx_data 中 4 个取字节的游标（各自步进 +4）|
| `crc_result` | reg | 16-bit | CRC16 运算中间值（初值 0xFFFF）|
| `crc_bit_index` | reg | 4-bit | 当前字节内的位编号（0~8，共 9 拍/字节）|
| `crc_byte_index` | reg | 8-bit | 当前正在做 CRC 的字节索引（从 1 到 32）|

## 4. 数据传输流程（FSM）

模块采用 **14 状态 one-hot FSM**，完整流程如下：

```
S_IDLE
  │ 写 UART_CTRL = 0x3（同时使能 TX 和 RX）
  ↓
S_INIT_UART_BAUD
  │ 写 UART_BAUD = 0x1B8（50MHz 时钟对应 115200bps）
  ↓
S_REC_FIRST_PACKET ◄─────────────────────────────────────────────┐
  │ need_to_rec_bytes ← 35，rec_bytes_index ← 0                  │
  ↓                                                               │（remain 包全部接收完毕后重新接收第一包）
S_CLEAR_UART_RX_OVER_FLAG ◄───────────────────────┐              │
  │ 写 UART_STATUS = 0（清除 RX 完成标志）          │              │
  ↓                                                │              │
S_WAIT_BYTE                                        │              │
  │ 读 UART_STATUS                                 │              │
  ↓                                                │              │
S_WAIT_BYTE2                                       │              │
  │ 轮询 STATUS[1]（RX_OVER_FLAG）                 │              │
  │  未置位 → 原地等待（下一拍继续检查）             │              │
  │  置位   → 读 UART_RX_REG                       │              │
  ↓                                                │              │
S_GET_BYTE                                         │              │
  │ rx_data[rec_bytes_index] ← mem_rdata[7:0]      │              │
  │ rec_bytes_index++                              │              │
  │  字节数 < 34 → 回 CLEAR_FLAG ─────────────────┘              │
  │  字节数 = 34（已收满 35 字节）→ 进入 CRC 阶段                 │
  ↓                                                               │
S_CRC_START                                                       │
  │ crc_result ← 0xFFFF，crc_byte_index ← 1                      │
  │ fw_file_size ← {rx_data[29..32]}（仅第一包有效）              │
  ↓                                                               │
S_CRC_CALC（共 32 字节 × 9 拍 = 288 拍）                          │
  │ CRC16-Modbus：字节 XOR 后逐位右移，LSB=1 则异或 0xA001        │
  ↓                                                               │
S_CRC_END                                                         │
  │ 校验：crc_result == {rx_data[34], rx_data[33]}？              │
  │  校验失败 → S_SEND_NAK（通知上位机重传）                      │
  │  校验通过 + 是第一包 → 计算 remain_count → S_SEND_ACK        │
  │  校验通过 + 是 remain 包 → remain_count-- → S_WRITE_MEM      │
  ↓                                                               │
S_WRITE_MEM（8 次迭代，每次写 1 个 32-bit 字）                     │
  │ 将 rx_data[1..32] 按序写入 ROM                                │
  │ 退出条件：write_mem_byte_index0 == 37                         │
  ↓                                                               │
S_SEND_ACK                                                        │
  │ 写 UART_TX = 0x06（ACK）                                      │
  │  remain_count > 0 → S_REC_REMAIN_PACKET                       │
  │  remain_count = 0 → S_REC_FIRST_PACKET ─────────────────────→┘
```

**NAK 处理：**

```
S_SEND_NAK
  │ 写 UART_TX = 0x15（NAK）
  │  remain_count > 0 → S_REC_REMAIN_PACKET（重传当前 remain 包）
  │  remain_count = 0 → S_REC_FIRST_PACKET（重传第一包）
```

## 5. ROM 写入机制

### 5.1 写入时序

从 `S_CRC_END` 进入 `S_WRITE_MEM` 时初始化：

```
write_mem_data  ← {rx_data[4], rx_data[3], rx_data[2], rx_data[1]}
write_mem_addr  ← 上一包末尾地址 - 4（首包为 0x0）
byte_index0~3   ← 5, 6, 7, 8
```

每拍写入一个 32-bit 字，8 次完成 32 字节：

| 迭代 | 写地址（相对包起始） | 写数据（小端字节序组装） |
|------|-------------------|------------------------|
| 1 | +0 | `{rx_data[4:1]}` |
| 2 | +4 | `{rx_data[8:5]}` |
| 3 | +8 | `{rx_data[12:9]}` |
| … | … | … |
| 8 | +28 | `{rx_data[32:29]}` |
| 9 | — | 退出（不写，index0=37 触发状态跳转）|

### 5.2 跨包地址连续性

每包结束时 `write_mem_addr` 多递增一次（退出拍仍执行 +4）。`S_CRC_END` 中通过 `-4` 修正，保证下一包从正确地址续写：

```
write_mem_addr[S_CRC_END] = write_mem_addr[上包结束] - 4
                           = 上包起始地址 + 32
```

每包在 ROM 中连续占用 32 字节，固件从 `0x0000_0000` 顺序写入。

## 6. CRC 算法

**CRC16-Modbus**，多项式 0x8005（反转形式 0xA001），初值 0xFFFF：

```
覆盖范围：rx_data[1] ~ rx_data[32]（共 32 字节）
每字节处理：1 拍 XOR + 8 拍逐位移位 = 9 拍/字节
总耗时：32 × 9 = 288 个时钟周期
```

Verilog 核心逻辑：

```verilog
S_CRC_CALC: begin
    if (crc_bit_index == 4'h0)          // 第 0 拍：XOR 当前字节
        crc_result <= crc_result ^ rx_data[crc_byte_index];
    else if (crc_bit_index < 4'h9) begin // 第 1~8 拍：逐位右移
        if (crc_result[0] == 1'b1)
            crc_result <= {1'b0, crc_result[15:1]} ^ 16'ha001;
        else
            crc_result <= {1'b0, crc_result[15:1]};
    end
end
```

校验值存储：`rx_data[33]` = CRC 低字节，`rx_data[34]` = CRC 高字节（小端存储，比较时重组为 `{rx_data[34], rx_data[33]}`）。

## 7. UART 外设寄存器访问

`uart_debug` 通过 RIB 总线间接操作 UART 外设（基地址 `0x3000_0000`）：

| 寄存器地址 | 访问 | 值 | 说明 |
|-----------|------|----|------|
| `0x30000000` | 写 | `0x3` | CTRL：同时使能 TX 和 RX |
| `0x30000004` | 读 | 轮询 bit[1] | STATUS：等待 RX_OVER_FLAG 置 1 |
| `0x30000004` | 写 | `0x0` | STATUS：写 0 清除 RX 完成标志 |
| `0x30000008` | 写 | `0x1B8` | BAUD：115200bps（50MHz 时钟） |
| `0x3000000C` | 写 | `0x06/0x15` | TX：发送 ACK(0x06) 或 NAK(0x15) |
| `0x30000010` | 读 | `[7:0]` | RX：读取接收到的字节 |

## 8. 本次修改记录

### 8.1 修改原因

原版 packet 为 131 字节，有效载荷 128 字节，适配大容量固件的批量传输。修改目标是将 packet 缩减至 **35 字节**，降低每包数据量，同步缩减内部接收缓冲区。

### 8.2 修改内容

| 修改项 | 修改前 | 修改后 |
|--------|--------|--------|
| `UART_FIRST_PACKET_LEN` | `8'd131` | `8'd35` |
| `UART_REMAIN_PACKET_LEN` | `8'd131` | `8'd35` |
| `rx_data` 缓冲区 | `reg[7:0] rx_data[0:131]`（132×8b）| `reg[7:0] rx_data[0:34]`（35×8b）|
| `fw_file_size` 提取位置 | `rx_data[61..64]`（超出新数组边界）| `rx_data[29..32]`（有效载荷末尾 4B）|
| `remain_packet_count` 公式 | `{7'h0, fw_file_size[31:7]} + 1`（÷128）| `fw_file_size[20:5] + 1`（÷32）|

### 8.3 新旧 Packet 对比

| 项目 | 修改前 | 修改后 |
|------|--------|--------|
| 总包大小 | 131 字节 | 35 字节 |
| 有效载荷 | 128 字节 | 32 字节 |
| fw_file_size 位置 | rx_data[61..64] | rx_data[29..32] |
| CRC 位置 | rx_data[129..130] | rx_data[33..34] |
| 每包 ROM 写次数 | 32 次（32 × 4B = 128B）| 8 次（8 × 4B = 32B）|
| CRC 计算耗时 | 1152 拍（128B × 9）| 288 拍（32B × 9）|
| 接收缓冲区大小 | 132 × 8-bit = 1056-bit | 35 × 8-bit = 280-bit |

### 8.4 验证结果

修改后运行全量 ISA 回归测试（`uart_debug_pin` 在仿真中固定为 0，模块不激活）：

```
48/48 全部 PASS（RV32I 39条 + RV32M 8条 + simple 1条）
```

处理器核心功能不受影响。
