# 半自动化测试脚本技术文档

**日期：** 2026-05-15  
**文件：** `tests/test_runner.py`

---

## 一、设计背景

原有测试流程需要手动在两个终端窗口分别运行 `tinyriscv_fw_downloader.py`（上传）和 `uart_recv.py`（接收），且每个测试用例都需要人工重复操作。`test_runner.py` 将两者整合到一个脚本中，实现：

- 自动遍历所有测试用例
- 固件上传 + UART 接收在**同一串口连接**内顺序完成
- 有 UART 输出的指令自动接收并解码
- 人工 pass/fail 输入
- 自动生成测试报告

---

## 二、串口复用原理

上传阶段（uart_debug 模式）和接收阶段（程序执行输出）使用**同一物理 COM 口**，时序上天然分离：

```
┌─────────────────────────────────────────────────────────┐
│ [上传阶段]                                               │
│   serial.write(packet)  ←→  uart_debug 模块接收         │
│   等待 ACK（3s 超时）                                    │
├─────────────────────────────────────────────────────────┤
│ [用户操作] 按住 Key1 → 按 Reset 松开 → CPU 开始执行      │
├─────────────────────────────────────────────────────────┤
│ [接收阶段]                                               │
│   serial.read(...)  ←  CPU 通过 UART 外设发送数据        │
│   等待首字节（20s 超时），静默 1.5s 后结束               │
└─────────────────────────────────────────────────────────┘
```

`serial.Serial` 对象在整个测试过程中保持打开，只需调整 `timeout` 参数在两个阶段之间切换。

---

## 三、关键操作步骤（UART 输出类测试）

板上有一个已知时序问题：直接按 Reset 可能导致 UART 线上出现错误数据。正确的复位操作顺序为：

```
Step 1: 按住 Key1（Uart_debug_en）── 脚本等待 Enter 确认
Step 2: 按下 Reset，然后松开（保持按住 Key1）── 脚本立即开始接收
       （CPU 开始执行，UART 外设输出数据）
Step 3: 数据接收完毕后可松开 Key1
```

脚本在提示 Step 1 后等待用户按 Enter，随后立即打印 Step 2 提示并调用 `recv_uart_output()`，不再插入额外等待，保证用户操作与接收窗口紧密衔接。

## 四、测试用例覆盖范围

### 4.1 自动发现（Basic_Inst_Example）

使用 `glob.glob('Basic_Inst_Example/*.data')` 自动发现所有基础指令测试，无需手动维护列表：

| 指令集 | 数量 | 验证方式 |
|--------|------|---------|
| ADD/ADDI/MUL/DIV/… | 24+ | 人工看板 + 输入 p/f |

### 4.2 手动列举（扩展/其他）

| 组 | 用例 | 有 UART 输出 | 输出解码 |
|----|------|------------|---------|
| Other_Example | PWM | ✗ | — |
| Extend_Inst_Example | sID | ✓ | ASCII 学号字符串 |
| Extend_Inst_Example | Temp(RT) | ✓ | 温度：raw×0.5°C |
| Extend_Inst_Example | IF2(IF) | ✓ | 发放膜电位（十进制+十六进制）|

## 五、文件格式支持

脚本内置 `convert_data_to_bin()` 函数（移植自 `tinyriscv_fw_downloader.py`），自动将 ASCII hex `.data` 文件转为小端二进制 `.bin`：

```
"300007b7\n"  →  bytes [0xB7, 0x07, 0x00, 0x30]（小端）
```

逻辑：对每行 8 字符十六进制，按 `data[6:8]`, `data[4:6]`, `data[2:4]`, `data[0:2]` 顺序写出 4 字节。

已有 `.data.bin` 的测试用例直接使用，节省转换时间。

## 六、用法

```bash
# 运行全部测试
python tests/test_runner.py COM3

# 只运行基础指令
python tests/test_runner.py COM3 --only basic

# 只运行扩展指令（sID / Temp / IF2）
python tests/test_runner.py COM3 --only extend

# 只运行其他示例（PWM）
python tests/test_runner.py COM3 --only other
```

## 九、已知限制

- sID 测试偶发接收问题（单独运行正常），原因待查，可能与 uart_debug 退出时序有关
- Basic_Inst_Example 无 UART 输出，pass/fail 需人工判断
- PWM 需要示波器或逻辑分析仪辅助验证
