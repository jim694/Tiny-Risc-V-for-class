**日期：** 2026-05-13  
**项目：** Tiny-Risc-V-for-class（RV32IM 三级流水线处理器核）  
**涉及提交：** `0bb65df`、`3407c76`、`91e65d9`

## 一、背景

ROM/RAM 迁移至片外后，所有存储器访问均经过 `rib_mem_bridge`（SoC 侧）和 `fpga_mem_bridge`（FPGA 侧）组成的 8-bit 串行桥接通道，每笔事务耗时 8 个系统时钟周期。原始 stall 机制仅在 bridge 事务进行中（`state != S_IDLE`）或有挂起请求（`pending=1`）时产生 `stall_o=1`，在实际运行 PWM 测试程序时暴露出多种指令跳过（吞指令）问题。

---

## 二、问题分析

### 2.1 RIB 总线仲裁关系

| 主设备 | 优先级 | 用途 |
|--------|--------|------|
| m3（uart_debug）| 最高 | 固件下载 |
| m0（EX 阶段）| 次高 | 数据读写（lw/sw）|
| m2（JTAG）| 次低 | 调试访问 |
| m1（IF 阶段）| 最低 | 取指（ROM，始终有请求）|

m1 优先级最低，意味着只要 m0 有请求，m1 就无法获得总线，`s0_cs_i=0`，bridge 看不到取指请求。

### 2.2 矛盾一：数据访问抢占取指，取指结果丢失

**场景：** lw/sw 目标为 RAM（`s1_cs_i=1`），bridge 为 m0 服务 8 周期。在 m0 事务启动时，m1 正在进行或等待 ROM 取指；m0 获得仲裁后 `s0_cs_i=0`，bridge 完成 m0 事务后直接置 `transaction_done=1` 释放 stall。

**后果：** 自由拍时 `s0_rdata_o` 持有的是上一次 ROM 事务的旧指令，不是当前 PC 对应的指令。`if_id` 捕获错误数据，指令跳过。

### 2.3 矛盾二：m0 访问非 bridge 外设，bridge 完全空闲

**场景：** sw 目标为 PWM/UART 等外设（`addr[31:28] ∉ {0,1}`），RIB 将 m0 授权给 s6/s3，m1 未获授权，`s0_cs_i=0`，`s1_cs_i=0`，`any_cs=0`。bridge 在 S_IDLE 无任何挂起请求，`stall_o=0`。

**后果：** 外设写本身 1 拍完成，但没有 stall 阻止 PC 前进，自由拍结束后下一拍同样无 stall（m0 可能仍持有总线），PC 连续前进 2 拍，中间那条指令从未被取，指令跳过。

### 2.4 `addr_match` 误判：s0_addr_i 在 m0 占总线时无效

bridge 原先在 S_LATCH 用 `s0_addr_i[9:2]` 做 ROM 地址比对。当 m0 被 RIB 授权（访问 s6/s1），RIB 将 `s0_addr_o` 置为 `ZeroWord`，导致 `cur_word_addr=0 ≠ addr_r`，addr_match 误判失败，已完成的 ROM 事务结果被丢弃，引发再次重取和自由拍时序错位。

---

## 三、修复方案

### 3.1 矛盾一修复：RAM 事务后强制 ROM 取指（`need_fetch_r`）

在 S_LATCH 中区分事务类型：

```verilog
S_LATCH:
  if (addr_match) begin
      if (mem_sel_r) begin
          // RAM 事务完成：锁存数据，设 need_fetch_r，stall 不释放
          s1_rdata_o   <= {ext_in_i, rdata_buf};
          need_fetch_r <= 1'b1;
      end else begin
          // ROM 事务完成：锁存指令，释放 stall
          s0_rdata_o       <= {ext_in_i, rdata_buf};
          transaction_done <= 1'b1;
          need_fetch_r     <= 1'b0;
      end
  end
```

`need_fetch_r=1` 时：
- `stall_o` 额外维持（`assign stall_o = ... || need_fetch_r`）
- 下一个 S_IDLE：`force_rom=1`，bridge 以 `pc_i[9:2]`（冻结 PC）为地址发起 ROM 取指
- ROM 取指完成后 `transaction_done=1`，`need_fetch_r=0`，一次性释放 stall

**效果：** 从 CPU 视角，lw/sw 结束的自由拍中，`s1_rdata_o` 持有数据，`s0_rdata_o` 持有当前 PC 的有效指令，pipeline 正确推进。

### 3.2 矛盾二修复：非 bridge 外设访问时强制 ROM 取指（`force_fetch_i`）

在 `tinyriscv_soc_top.v` 中检测 m0 访问非 bridge slave：

```verilog
wire mem_bridge_force_fetch = m0_req_i
                            & (m0_addr_i[31:28] != 4'h0)   // 非 ROM
                            & (m0_addr_i[31:28] != 4'h1);  // 非 RAM
```

连接到 bridge 新增端口 `force_fetch_i`。bridge 内：

```verilog
wire force_rom = need_fetch_r || force_fetch_i;
wire pending   = (any_cs || force_rom) && (state == S_IDLE) && !transaction_done;
assign stall_o = (state != S_IDLE) || pending || need_fetch_r;
```

当 `force_fetch_i=1` 时，bridge 立即进入 ROM 取指事务，stall 维持 8 个周期，保证 m0 完成外设写的同时 ROM 事务也完成，自由拍时 `s0_rdata_o` 持有正确指令。

### 3.3 `addr_match` 修复：始终用 `pc_i` 做 ROM 地址比对

```verilog
// 修复前：
wire [7:0] cur_word_addr = mem_sel_r ? s1_addr_i[9:2] : s0_addr_i[9:2];

// 修复后：
wire [7:0] cur_word_addr = mem_sel_r ? s1_addr_i[9:2] : pc_i[9:2];
```

`pc_i`（= m1_addr_i = CPU PC 输出）在 Hold_Freeze 期间保持不变，不依赖 RIB 授权状态，消除了 m0 占总线时 `s0_addr_i=0` 导致的误判。分支检测仍然有效：若跳转改变 PC，`pc_i[9:2] ≠ addr_r`，addr_match=0，触发重取。

### 3.4 `m1_data_o` 直通修复（`rib.v`）

m1（取指）始终访问 s0（ROM），因此将 m1 的读数据直接接 `s0_data_i`，不经 RIB 仲裁路径：

```verilog
// 修复前（默认值）：
m1_data_o = `INST_NOP;

// 修复后：
m1_data_o = s0_data_i;   // m1 始终取 ROM，直通 s0_data_i
```

保证自由拍时 `if_id` 捕获 `m1_data_o = s0_rdata_o`（刚完成的 ROM 事务结果），与 m0 是否持有总线无关。

## 四、修复后 stall 逻辑总览

```verilog
wire force_rom = need_fetch_r || force_fetch_i;
wire pending   = (any_cs || force_rom) && (state == S_IDLE) && !transaction_done;
assign stall_o = (state != S_IDLE) || pending || need_fetch_r;
```

| 触发路径 | stall 来源 | 持续 | 结束条件 |
|---------|-----------|------|---------|
| 普通取指（m1→ROM）| `state!=IDLE` + `pending` | 8 周期 | ROM S_LATCH → `transaction_done` |
| lw/sw → RAM | `state!=IDLE` + `need_fetch_r` | 8+8 周期 | RAM→ROM 双事务均完成 |
| sw/lw → 外设 | `force_fetch_i` → `pending` | 8 周期 | 强制 ROM 取指完成 |

所有路径结束时，自由拍（`transaction_done=1`，stall=0）中 `s0_rdata_o` 均持有当前 PC 的有效指令。

## 五、新增接口

| 模块 | 新增端口/信号 | 说明 |
|------|-------------|------|
| `rib_mem_bridge` | `input pc_i[31:0]` | 冻结 PC，用于强制取指地址和 addr_match |
| `rib_mem_bridge` | `input force_fetch_i` | 外设访问时强制取指触发 |
| `tinyriscv_soc_top` | `wire mem_bridge_force_fetch` | 检测 m0 访问非 bridge slave |

## 七、已知限制

lw 从 ROM 地址（`0x0xxx_xxxx`）读数据：bridge 做 ROM 事务，`addr_r` 为数据地址，`cur_word_addr = pc_i[9:2]`（PC），两者不等 → addr_match=0 → 无限重试。当前测试程序中未出现此场景（数据均在 RAM），若将来有只读查找表放置于 ROM，需要额外区分 m0/m1 的 ROM 访问路径。
