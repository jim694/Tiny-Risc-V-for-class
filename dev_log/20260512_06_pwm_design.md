# PWM 外设设计规划

**日期：** 2026-05-12  
**项目：** Tiny-Risc-V-for-class（RV32IM 三级流水线处理器核）

---

## 一、功能概述

添加一个 4 通道 PWM 外设，挂载在 RIB 总线上作为 Slave 6（地址 `0x6xxx_xxxx`）。  
每个通道独立配置输出周期与高电平时长，并可单独使能。

---

## 二、寄存器映射

| 寄存器 | 总线地址 | 宽度 | 含义 |
|--------|---------|------|------|
| A0 | `0x60000000` | uint16 | 通道 0 总周期（系统时钟数）|
| A1 | `0x60010000` | uint16 | 通道 1 总周期 |
| A2 | `0x60020000` | uint16 | 通道 2 总周期 |
| A3 | `0x60030000` | uint16 | 通道 3 总周期 |
| C  | `0x60040000` | 4-bit | 通道使能（bit[i]=1 使能通道 i）|
| B0 | `0x60100000` | uint16 | 通道 0 高电平时长（系统时钟数）|
| B1 | `0x60110000` | uint16 | 通道 1 高电平时长 |
| B2 | `0x60120000` | uint16 | 通道 2 高电平时长 |
| B3 | `0x60130000` | uint16 | 通道 3 高电平时长 |

**总线数据格式：**  
A 与 B 寄存器为 uint16，读写时占 32-bit 总线数据的低 16 位 `[15:0]`，高 16 位忽略（读返回 0）。  
C 寄存器读写使用 `data[3:0]`。

### 2.1 地址解码

将总线地址 `addr[27:0]`（去掉高 4 位 slave 选择位）按以下位域解码：

```
addr[27:0] 关键位：
  bit[20]    0 = A/C 组；1 = B 组
  bit[18]    （addr[20]=0 时有效）0 = A 寄存器；1 = C 寄存器
  bit[17:16] 通道索引（0~3），对 A、B 寄存器有效
```

| addr[20] | addr[18] | addr[17:16] | 访问目标 |
|----------|----------|-------------|---------|
| 0 | 0 | ch | A[ch] |
| 0 | 1 | — | C |
| 1 | — | ch | B[ch] |

## 三、PWM 生成逻辑

每个通道 i 包含一个 16-bit 计数器 `cnt[i]`，行为如下：

```
每个系统时钟上升沿：
    if cnt[i] < A[i] - 1:
        cnt[i] += 1
    else:
        cnt[i]  = 0

输出逻辑：
    pwm_o[i] = C[i] && (cnt[i] < B[i])
```

**边界情况处理：**

| 条件 | 输出行为 |
|------|---------|
| `C[i] = 0` | 输出恒为 0 |
| `A[i] = 0` | 计数器不计数，输出恒为 0 |
| `B[i] = 0` | 输出恒为 0（高电平时长为零）|
| `B[i] >= A[i]` | 输出恒为 1（100% 占空比）|

**寄存器更新时机：**  
写入 A[i] 或 B[i] 立即生效（下一时钟周期起）。若在计数中途修改 A[i]，计数器在本周期结束后使用新值；若新 A[i] 小于当前 cnt[i]，计数器在下一拍归零。

## 四、模块接口设计

```verilog
module pwm (
    input  wire        clk,
    input  wire        rst,

    // RIB Slave 6 总线接口（与其他外设相同规格）
    input  wire [31:0] addr_i,
    input  wire [31:0] data_i,
    output reg  [31:0] data_o,
    input  wire        we_i,

    // PWM 输出引脚
    output reg  [3:0]  pwm_o
);
```

**总线接口行为：**

- **写（we_i=1）：** 根据地址解码，将 `data_i[15:0]`（或 `data_i[3:0]`）写入对应寄存器
- **读（we_i=0）：** 将对应寄存器值零扩展后输出到 `data_o`
- 访问不在映射范围内的地址：读返回 0，写忽略

## 五、RIB 总线集成

### 5.1 Slave 编号

```
Slave 0：ROM  (0x0xxx_xxxx) ← bridge
Slave 1：RAM  (0x1xxx_xxxx) ← bridge
Slave 2：（已删除 - Timer）
Slave 3：UART (0x3xxx_xxxx) ← 保留
Slave 4：（已删除 - GPIO）
Slave 5：（已删除 - SPI）
Slave 6：PWM  (0x6xxx_xxxx) ← 新增
```

路由判断：`addr[31:28] == 4'b0110`（即 `== 6`）

### 5.2 需要修改的文件

| 文件 | 改动内容 |
|------|---------|
| `rtl/core/rib.v` | 新增 slave 6 端口与路由分支（`parameter slave_6 = 4'b0110`）|
| `rtl/soc/tinyriscv_soc_top.v` | 新增 `u_pwm` 例化，连接 RIB slave 6 与顶层 PWM 引脚 |
| `rtl/perips/pwm.v` | **新建**，实现 PWM 模块 |

### 5.3 顶层新增端口

```verilog
// tinyriscv_soc_top.v 新增输出端口
output wire [3:0] pwm_o
```

## 六、内部结构

```
pwm.v
├── 寄存器堆
│   ├── A[3:0][15:0]   总周期寄存器（同步写，复位为 0）
│   ├── B[3:0][15:0]   高电平时长寄存器（同步写，复位为 0）
│   └── C[3:0]         使能寄存器（同步写，复位为 0）
├── 地址解码逻辑（组合）
├── 总线读回逻辑（组合）
└── PWM 生成（×4，独立）
    ├── cnt[i][15:0]   16-bit 计数器（同步）
    └── pwm_o[i]       输出（组合，由 C[i]、cnt[i]、B[i] 决定）
```

## 七、CPU 访问方式（MMIO）

PWM 寄存器通过**内存映射 I/O（MMIO）**访问，CPU 使用普通 `sw`/`lw` 指令读写，无需专用接口。

### 7.1 控制流程

```
CPU 执行 sw 指令（目标地址 0x6xxx_xxxx）
    → RIB 总线 M0 主设备仲裁
    → addr[31:28] == 6 → 路由到 Slave 6（PWM）
    → PWM 模块写入对应内部寄存器
    → 硬件自动产生 PWM 波形
```

### 7.2 汇编示例

配置通道 0：周期 100 个时钟，占空比 50%，使能输出：

```asm
# A0 = 100（总周期）
li   t0, 0x60000000
li   t1, 100
sw   t1, 0(t0)

# B0 = 50（高电平时长）
li   t0, 0x60100000
li   t1, 50
sw   t1, 0(t0)

# C = 0x1（使能通道 0）
li   t0, 0x60040000
li   t1, 1
sw   t1, 0(t0)
```

等价 C 代码：

```c
*(volatile uint32_t*)0x60000000 = 100;  // A0
*(volatile uint32_t*)0x60100000 = 50;   // B0
*(volatile uint32_t*)0x60040000 = 0x1;  // 使能通道 0
```

### 7.3 注意事项

- `volatile` 修饰符（C）防止编译器优化掉对 MMIO 地址的访问
- 写入后硬件立即生效，无需轮询确认
- 读回：`lw t0, 0(addr)` 可验证寄存器当前值

## 八、寄存器更新策略（方案一：写时自动复位）

写 A[i] 或 B[i] 时，对应通道计数器 cnt[i] 立即清零，新周期从头开始。

```verilog
always @ (posedge clk) begin
    if      (write_ch[i])        cnt[i] <= 0;        // 写寄存器 → 立即复位
    else if (cnt[i] >= A[i] - 1) cnt[i] <= 0;        // 周期末 → 归零
    else                         cnt[i] <= cnt[i] + 1;
end
```

**硬件开销：** 约 1～2 LUT / 通道，4 通道共约 4～8 LUT，无额外触发器。

## 九、设计决策汇总

| 问题 | 决策 |
|------|------|
| 计数器/寄存器位宽 | 32-bit（最大周期 4,294,967,295 时钟）|
| 寄存器更新时机 | 写时计数器立即复位（方案一）|
| C 寄存器复位值 | 0（所有通道默认关闭）|
| 读写对称性 | 支持回读 |
| 地址范围外访问 | 读返回 0，写忽略 |

## 十、测试计划

### 10.1 参考测试程序分析（tests/Other_Example/PWM/PWM.c）

```c
*(unsigned int *)0x60000000 = 100000000; // A0：周期 1 亿时钟（@100MHz = 1s，2Hz）
*(unsigned int *)0x60100000 = 50000000;  // B0：高电平 5000 万时钟（占空比 50%）
*(unsigned int *)0x60010000 = 50000000;  // A1：周期 5000 万（@100MHz = 0.5s，1Hz）
*(unsigned int *)0x60110000 = 25000000;  // B1：高电平 2500 万
*(unsigned int *)0x60020000 = 4000000;   // A2：周期 400 万
*(unsigned int *)0x60120000 = 2000000;   // B2：高电平 200 万
*(unsigned int *)0x60030000 = 8000000;   // A3：周期 800 万
*(unsigned int *)0x60130000 = 4000000;   // B3：高电平 400 万
*(unsigned int *)0x60040000 = 15;        // C：使能全部 4 通道（0xF）
```

程序结构：标准 C 运行时启动（`_start`）→ `main()` 写 PWM 寄存器 → 返回 → `s10(x26)=1` → 原地循环。

### 10.2 直接仿真的限制

该测试程序**无法直接在当前仿真环境中运行**，原因如下：

| 限制 | 说明 |
|------|------|
| **RAM 容量不足** | C 运行时将栈初始化到 `0x10004000`，远超当前 RAM 上限 `0x1000003C`（64B），栈写入会静默回绕到 `_ram[0]`，数据必然损坏 |
| **仿真周期过长** | A0 = 100,000,000 时钟，在仿真中观察一个完整 PWM 周期需 2 亿个时钟（一写一读），远超 testbench 默认超时（500000ns = 25000 周期）|
| **无数字比较** | 程序不检查 PWM 输出是否正确，仅写寄存器后退出；x27(s11) 始终为 0，testbench 无法自动判断通过/失败 |

### 10.3 仿真验证计划（可执行部分）

仿真可验证 PWM 模块的**数字逻辑正确性**，需编写专用裸机测试程序（不含 C 运行时），使用小数值使仿真在合理周期内完成：

**测试项 1：寄存器读写与地址解码**

| 操作 | 验证内容 |
|------|---------|
| 写 A0=100，读回 A0 | 地址解码正确（`addr[20]=0, addr[18]=0, addr[17:16]=00`）|
| 写 B0=50，读回 B0 | B 组地址解码正确（`addr[20]=1`）|
| 写 C=0xF，读回 C | 使能寄存器读写正确 |
| 写地址范围外，读回 | 返回 0，写忽略 |

**测试项 2：PWM 波形逻辑（使用小 A/B 值）**

使用 A=10、B=5，在波形中观察 `pwm_o[0]`：
- 前 5 个时钟输出高（cnt < B=5）
- 后 5 个时钟输出低（cnt >= 5）
- 第 10 个时钟计数器归零（cnt=9 >= A-1=9）

**测试项 3：使能控制**

- C=0 时 `pwm_o` 全低
- C=0x5（通道 0、2 使能）时只有 `pwm_o[0]`、`pwm_o[2]` 输出

**测试项 4：写时计数器复位**

写入 A[0] 时，通过波形确认 cnt[0] 立即归零，新周期从头开始。

### 10.4 上板验证计划（必须）

以下验证**必须上板执行**：

| 验证项 | 方法 |
|--------|------|
| 实际 PWM 频率 | 示波器或逻辑分析仪测量 `pwm_o` 引脚频率 |
| 占空比精度 | 示波器测量高电平时长 / 总周期 |
| LED 闪烁效果 | 将 `pwm_o` 接 LED，肉眼确认 PWM.c 中各通道的不同闪烁频率 |
| 多通道独立性 | 同时观察 4 路输出，确认互不干扰 |
| 运行时修改 | CPU 在线修改 A/B 后，输出立即切换到新频率 |

**PWM.c 运行的前置条件（上板需要）：**
- RAM 需扩展至支持 C 运行时（至少 16KB），或修改链接脚本减小栈空间
- 上板时钟频率决定实际 PWM 周期（A=100,000,000 在 100MHz 时 = 1s）

### 10.5 测试顺序建议

```
Step 1：仿真验证寄存器读写与地址解码        ← 纯数字逻辑，无需硬件
Step 2：仿真验证 PWM 波形逻辑（小 A/B 值）  ← 纯数字逻辑，无需硬件
Step 3：上板验证 PWM.c 四通道输出效果       ← 需要 FPGA 硬件 + RAM 扩展
```
