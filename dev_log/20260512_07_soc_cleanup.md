## 一、JTAG 接口移除

### 1.1 背景

原设计包含一套基于 RISC-V Debug Spec 的软核 JTAG 调试接口（`jtag_top` / `jtag_driver` / `jtag_dm`），可通过外部 JTAG 适配器（如 J-Link + OpenOCD）实现 CPU halt/resume、单步执行、寄存器读写等功能。

课程项目中该接口从未实际使用：TCK/TMS/TDI/TDO 四个引脚在 XDC 中未被约束，也没有外部调试器连接。FPGA 内置 JTAG（Xilinx 原生）与本软核 JTAG 是两套完全独立的系统，前者用于 Vivado 下载比特流和 ILA 抓波形，后者是运行在 FPGA 逻辑上的用户设计。

### 1.2 两套 JTAG 的区别

| | FPGA 内置 JTAG | 软核 JTAG（已移除） |
|--|--|--|
| 调试对象 | FPGA 芯片本身 | RISC-V CPU 软件 |
| 实现层 | 硅片固化 | Verilog RTL |
| 使用工具 | Vivado / ILA | GDB + OpenOCD |
| 连接方式 | 专用引脚（芯片内部） | 普通用户 IO |

### 1.3 移除内容

| 文件 | 改动 |
|------|------|
| `rtl/soc/tinyriscv_soc_top.v` | 删除 `halted_ind`、`jtag_TCK/TMS/TDI/TDO` 顶层端口；删除 6 条 jtag 内部 wire；删除 `jtag_top` 例化；m2 接口接零 |
| `rtl/core/tinyriscv.v` | 删除 `jtag_reg_*`、`jtag_halt_flag_i`、`jtag_reset_flag_i` 端口及子模块连接 |
| `rtl/core/ctrl.v` | 删除 `jtag_halt_flag_i` 输入和对应 `Hold_Id` 分支 |
| `rtl/core/regs.v` | 删除 jtag 读写端口、写 always 分支、jtag 读 always 块 |
| `rtl/core/pc_reg.v` | 删除 `jtag_reset_flag_i`，复位条件简化为 `rst == RstEnable` |

**保留但不例化：** `jtag_top.v` / `jtag_driver.v` / `jtag_dm.v` 源文件保留在仓库，以备将来流片时重新接入。

### 1.4 m2 主设备处理

RIB 总线的 Master 2 原本由 JTAG 用于内存访问。移除 JTAG 后，m2 接口在 `tinyriscv_soc_top.v` 中接零禁用：

```verilog
assign m2_addr_i = `ZeroWord;
assign m2_data_i = `ZeroWord;
assign m2_req_i  = `RIB_NREQ;
assign m2_we_i   = `WriteDisable;
```

RIB 总线模块 `rib.v` 无需修改，m2 永远不会获得总线授权。

### 1.5 关于流片的注意事项

若将来项目进行 ASIC 流片，应在流片前将 JTAG 重新接入。流片后若无 JTAG，调试手段仅剩 UART TX 打印和 succ/over 引脚，无法 halt CPU 或读取寄存器状态，调试效率极低。重新接入时还需在 XDC（或流片约束文件）中为 TCK 添加 `create_clock` 约束及跨时钟域 false_path 声明。

## 二、fpga_mem_bridge 片内集成

### 2.1 背景

ROM/RAM 迁移片外后，SoC 侧使用 `rib_mem_bridge`（7 状态 FSM，8 周期/事务）通过 8-bit 串行接口与 FPGA 侧的 `fpga_mem_bridge` 通信。

原设计将 `ext_mem_out[7:0]` 和 `ext_mem_in[7:0]` 作为 `tinyriscv_soc_top` 的顶层 IO 端口，预留给 SoC 与 FPGA 分板部署的场景。课程项目中两个模块均综合在同一块 FPGA 上，顶层端口会被 Vivado 绑定到物理引脚，造成无效的外部 IO 占用。

### 2.2 修改内容

将 `ext_mem_out` / `ext_mem_in` 从顶层端口改为内部 wire，并在 `tinyriscv_soc_top.v` 内部直接例化 `fpga_mem_bridge`：

```verilog
// 片内桥接互联信号
wire [7:0] ext_mem_out_w;
wire [7:0] ext_mem_in_w;

rib_mem_bridge u_rib_mem_bridge(
    ...
    .ext_out_o(ext_mem_out_w),
    .ext_in_i(ext_mem_in_w),
    ...
);

fpga_mem_bridge u_fpga_mem_bridge(
    .clk(clk),
    .rst(rst),
    .ext_in_i(ext_mem_out_w),
    .ext_out_o(ext_mem_in_w)
);
```

### 2.3 ROM 初始化时序

`fpga_mem_bridge` 内的 `_rom[0:255]` 上电默认全零。固件通过以下时序加载：

```
rst = 1（复位高电平）
    → uart_debug 激活（req_o = rst & debug_en_i）
    → uart_debug 通过 RIB → rib_mem_bridge → fpga_mem_bridge 写入 _rom
rst = 0（释放复位）
    → CPU 从地址 0x00000000 开始执行已加载的程序
```

CPU 在 rst 高电平期间处于复位状态，不会执行任何指令，因此固件下载与 CPU 执行不会冲突。

## 三、当前顶层端口汇总

```
tinyriscv_soc_top
    input  clk              // 系统时钟（50MHz，Y18）
    input  rst              // 复位，高电平有效（F20）
    output over             // 测试完成指示（未约束）
    output succ             // 测试成功指示（F19）
    input  uart_debug_pin   // 固件下载使能（M13）
    output uart_tx_pin      // UART 发送（G16）
    input  uart_rx_pin      // UART 接收（G15）
    output pwm_o[3:0]       // PWM 输出（E21/D20/C20/E14）
```

`over` 引脚暂未在 XDC 中约束（待确认板上可用引脚后补充）。
